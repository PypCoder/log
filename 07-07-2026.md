# LoRA & QLoRA — Low-Rank Adaptation for Efficient Fine-Tuning

Full fine-tuning of a large model means updating every weight matrix in every layer, which requires storing a full-precision gradient and optimizer state (Adam alone needs 2 extra copies of the weights) for *all* parameters. For a 7B model, that's well over 100GB of memory just for training state — completely out of reach on consumer hardware. LoRA sidesteps this by exploiting a simple empirical observation about *how much* a model's weights actually need to change during adaptation.

## The Low-Rank Hypothesis

When you fine-tune a pretrained model on a downstream task, the *update* to the weights — not the weights themselves — tends to have a low "intrinsic rank." In other words, even though the full weight matrix $W_0$ is huge ($d \times k$), the meaningful change $\Delta W$ needed to specialize it lives in a much smaller subspace.

Instead of learning a dense update $\Delta W \in \mathbb{R}^{d \times k}$, LoRA decomposes it into the product of two skinny matrices:

$$
\Delta W = BA
$$

Where $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times k}$, and the rank $r \ll \min(d, k)$ (often 4, 8, or 16). The adapted forward pass becomes:

$$
h = W_0 x + \Delta W x = W_0 x + BA x
$$

*   **Frozen backbone:** $W_0$ is frozen entirely — no gradients, no optimizer state.
*   **Trainable delta:** Only $A$ and $B$ receive gradients. $A$ is initialized with random Gaussian noise, $B$ is initialized to **zero**, so $\Delta W = 0$ at the start of training — the adapted model is identical to the base model on step one.
*   **Parameter count:** A $4096 \times 4096$ attention projection has ~16.8M parameters. At rank $r=8$, LoRA needs $4096 \times 8 \times 2 \approx 65K$ — roughly **0.4%** of the original.

A scaling factor $\alpha$ (typically set so $\alpha/r$ stays constant across rank choices) controls how strongly the adapter influences the frozen weights:

$$
h = W_0 x + \frac{\alpha}{r} BA x
$$

Critically, because $\Delta W$ collapses back into a single matrix of the *same shape* as $W_0$, LoRA adapters can be merged into the base weights after training — **zero inference latency overhead**, unlike adapter-layer methods that add extra sequential compute.

## Where It's Applied

LoRA is typically injected only into the attention projection matrices ($W_q$, $W_k$, $W_v$, $W_o$) rather than every linear layer in the network — empirically this captures most of the adaptation benefit while keeping the trainable footprint minimal.

```python
import torch
import torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base_layer: nn.Linear, rank: int = 8, alpha: int = 16):
        super().__init__()
        self.base = base_layer
        self.base.weight.requires_grad = False  # freeze W0

        d_out, d_in = base_layer.weight.shape
        self.A = nn.Parameter(torch.randn(rank, d_in) * 0.01)
        self.B = nn.Parameter(torch.zeros(d_out, rank))  # zero init -> ΔW = 0
        self.scale = alpha / rank

    def forward(self, x):
        frozen_out = self.base(x)
        delta = (x @ self.A.T) @ self.B.T
        return frozen_out + self.scale * delta
```

## QLoRA: Compressing the Frozen Backbone Too

LoRA already shrinks the *trainable* memory footprint, but the frozen base model still has to sit in VRAM at full precision. QLoRA attacks this by quantizing $W_0$ down to 4-bit while keeping the LoRA adapters ($A$, $B$) in higher precision — directly reusing the block-wise quantization ideas from the [quantization entry](06-07-2026.md).

*   **NF4 (NormalFloat4):** A quantization data type built specifically for weights that follow a roughly Gaussian distribution (which pretrained neural net weights do). Instead of uniformly-spaced INT4 levels, NF4 places quantization bins at the quantiles of a standard normal distribution — information-theoretically optimal for normally-distributed data.
*   **Double Quantization:** Even the FP32 scaling constants used per quantization block consume memory at scale. QLoRA quantizes *those constants themselves* with a second, coarser quantization pass, saving roughly 0.4 bits per parameter on average.
*   **Paged Optimizers:** Uses NVIDIA unified memory to automatically page optimizer states between GPU and CPU RAM when VRAM spikes during gradient checkpointing, preventing OOM crashes on long sequences.
*   **Computation dtype:** Weights are *stored* in 4-bit but *dequantized on the fly* to bfloat16 for the actual matrix multiply — accuracy of the forward/backward pass isn't sacrificed, only storage.

The net effect: QLoRA makes it possible to fine-tune a 65B-parameter model on a single 48GB GPU, and a 7B model comfortably on a single consumer card — with performance close to full 16-bit fine-tuning.

## Comparison

| Method | Trainable Params | VRAM (7B model, approx.) | Backbone Precision | Inference Overhead |
| :--- | :--- | :--- | :--- | :--- |
| **Full Fine-Tuning** | 100% | ~60–80GB | FP16/BF16 | None |
| **LoRA** | ~0.1–1% | ~16–20GB | FP16/BF16 | None (mergeable) |
| **QLoRA** | ~0.1–1% | ~6–10GB | NF4 (4-bit) | None (merge after dequant) |

For SERAPH-scale experiments, this is the practical path: freeze the ESM-2 backbone, LoRA-adapt only the projection layers relevant to the downstream task, and skip QLoRA's 4-bit backbone only if the base model already fits comfortably in VRAM at full precision.
