# KV-Cache & FlashAttention

The fundamental bottleneck in LLM generation isn't compute power—it's memory bandwidth. Generating text token-by-token forces the hardware to constantly shuffle data around or recalculate the exact same context over and over.

---

## KV-Caching: Stopping Redundant Math

When a model generates text, it looks at everything written so far to predict the next token. If it has already generated 50 tokens, predicting token 51 shouldn't require re-reading tokens 1 through 50 from scratch.

* **The Problem:** Standard attention naturally recalculates the Key ($K$) and Value ($V$) matrices for every historical token at every single generation step. This scales the computational cost quadratically ($O(N^2)$).
* **The Fix:** Store the calculated $K$ and $V$ tensors of the past tokens directly in the GPU VRAM. For token 51, the model only computes $K$ and $V$ for token 50, flings it into the cache, and performs attention over the entire cached matrix.
* **The Trade-off:** We trade VRAM capacity for speed. Computation drops from $O(N^2)$ to $O(N)$, but long-context windows will aggressively devour GPU memory.

---

## FlashAttention: Minimizing GPU Memory Traffic

Even with a KV-cache, the attention calculation itself is highly inefficient on a hardware level because of the constant data transfer between two memory tiers on the GPU: **HBM** (large, slow main memory) and **SRAM** (tiny, fast on-chip cache).

* **The Problem:** Standard attention computes the intermediate attention matrix ($S = QK^T$, an $N \times N$ matrix) and writes it to the slow HBM. Then it reads it back to do softmax, writes it back, and reads it again to multiply by $V$. This constant round-trip bottlenecks the GPU's tensor cores.
* **The Fix:** Don't change the math, change the memory management via **tiling**. FlashAttention loads small blocks of Queries, Keys, and Values into the fast SRAM cache, computes attention locally using a mathematical trick to handle softmax incrementally block-by-block, and outputs the final result directly.
* **The Result:** The massive intermediate $N \times N$ matrix is never materialized in the slow main memory. It keeps the computation on the fast chip, yielding a $2\times$ to $4\times$ speedup entirely through hardware-aware engineering.
