# Model Quantization Architecture (GGUF vs. AWQ vs. GPTQ)

Large Language Model (LLM) inference is bottlenecked by memory bandwidth, not compute. Modern GPUs spend the vast majority of their time idling while waiting for weights to be loaded from VRAM into the streaming multiprocessors. Post-Training Quantization (PTQ) solves this by mapping high-precision weights (FP16/BF16) to lower precision (typically INT4), heavily reducing memory traffic. 

However, naively rounding weights destroys the model's perplexity. Today, I learned how the three dominant quantization frameworks—GPTQ, AWQ, and GGUF—mathematically and structurally solve this problem for different hardware targets.

---

## 1. GPTQ: Generalized Post-Training Quantization

GPTQ is a one-shot weight quantization method based on approximate second-order information. It is heavily optimized for GPU (CUDA) execution.

Instead of rounding weights in isolation, GPTQ calculates the error introduced by quantizing a single weight and mathematically distributes that error to the remaining *unquantized* weights in the same layer. It achieves this by attempting to minimize the squared error between the output of the original layer and the quantized layer:

$$ \arg\min_{\hat{W}} \| W X - \hat{W} X \|_2^2 $$

Where $W$ is the weight matrix and $X$ is the layer input. GPTQ solves this row by row using the inverse of the Hessian matrix $H$:

$$ H = 2 X X^T $$

When a weight is quantized, the required update to the remaining weights $\Delta w$ is computed using the corresponding row of the inverse Hessian matrix $H^{-1}$. By processing weights in batches and applying these error compensations, GPTQ preserves accuracy even at 4-bit or 3-bit precision.

## 2. AWQ: Activation-Aware Weight Quantization

While GPTQ looks at the weights, AWQ operates on the realization that **weights are not equally important, and their importance is dictated by their corresponding activations.** 

AWQ discovers that roughly 1% of the weights (the "salient" weights) handle the largest activation magnitudes. If you quantize these specific channels naively, the model collapses. Instead of keeping them in FP16 (which creates hardware inefficiencies during matrix multiplication), AWQ scales the salient weights *up* and scales their corresponding activations *down* before quantization:

$$ Y = W X = (W \cdot S) \cdot (S^{-1} X) = \hat{W} X $$

Where $S$ is a diagonal scaling matrix. The optimal scaling factor $s^*$ is found by minimizing the reconstruction error on a small calibration dataset:

$$ s^* = \arg\min_s \| WX - \text{Quantize}(W \cdot s)(s^{-1} X) \| $$

By amplifying the salient weights, they suffer significantly less relative quantization error when mapped to INT4. Because all weights remain in INT4, AWQ allows for highly optimized, uniform GPU kernels (like those used in `vLLM` and `TGI`), offering better latency and perplexity retention than GPTQ.

## 3. GGUF: The CPU/Mixed Inference Standard

Unlike GPTQ and AWQ (which are algorithmic implementations), **GGUF (GPT-Generated Unified Format)** is primarily a binary file format and execution ecosystem (via `llama.cpp`). It is the absolute standard for CPU, Apple Silicon, and mixed CPU/GPU inference.

Mathematically, GGUF relies on **block-wise quantization** (known as *k-quants*). Instead of treating the whole tensor at once, GGUF groups weights into blocks (e.g., 32 weights). Each block shares a single FP16 scaling factor.

$$ w \approx s \cdot q $$

*Where $s$ is the scale and $q \in [-8, 7]$ for 4-bit signed integers.*

Advanced `k-quants` (like `Q4_K`) use a nested super-block structure. A super-block of 256 weights will contain 8 sub-blocks of 32 weights. The super-block holds a master scale, and each sub-block holds a 6-bit sub-scale. 

**Key advantages of GGUF:**
* **Mixed Precision:** GGUF models rarely use a single bit-width. A `Q4_K_M` model quantizes robust feed-forward layers to 4-bit, but keeps sensitive attention layers at 6-bit.
* **Memory Mapping (mmap):** GGUF allows models to be memory-mapped, meaning the OS handles loading parts of the model into RAM only when needed, drastically speeding up load times.
* **Tensor Offloading:** It inherently supports offloading specific computational graphs to the GPU while leaving the rest on the CPU.

## 4. Architectural Comparison

| Feature | GGUF | AWQ | GPTQ |
| :--- | :--- | :--- | :--- |
| **Primary Hardware** | CPU, Apple Mac, Mixed CPU+GPU | Dedicated GPU (CUDA) | Dedicated GPU (CUDA) |
| **Core Mechanism** | Block-wise k-quants & mixed precision | Activation-aware weight scaling | Hessian-based error compensation |
| **Best Serving Engines** | `llama.cpp`, Ollama, LM Studio | `vLLM`, Hugging Face TGI | ExLlamaV2, AutoGPTQ |
| **Calibration Data** | Not required | Required (Activation patterns) | Required (Hessian calculation) |
