# Latent Space Anomaly Detection — Reconstruction Loss & Zero-Day Threshold Dynamics

Signature-based and classical statistical IDS approaches operate on an assumption that breaks the moment traffic features scale past a handful of dimensions: that "normal" can be captured by fixed rules or low-order distributions. Modern network traffic (NetFlow records, packet captures reduced to feature vectors) routinely spans 40+ correlated dimensions — duration, byte counts per direction, flag distributions, protocol encodings, inter-arrival timing. Autoencoders sidestep the dimensionality problem entirely by learning *where normal traffic actually lives*, turning "abnormal" into a geometric/statistical judgment rather than a rule match.

## 1. Why Traditional Methods Collapse in High Dimensions

* **Signature-based (Snort/Suricata-style):** requires a known pattern to match against. Zero-day = no signature exists yet by definition — the method is structurally reactive, only useful *after* an attack has been caught elsewhere and a rule authored for it.
* **Per-feature statistical thresholds (fixed z-score):** treat each feature independently, missing multivariate anomalies. A connection with a normal `bytes_sent` and a normal `duration` individually can still have an abnormal *ratio* between the two — invisible to univariate checks.
* **Distance-based methods (kNN, Mahalanobis on raw features):** fall apart due to the curse of dimensionality. As dimensionality $d$ increases, pairwise Euclidean distances concentrate — the contrast between the nearest and farthest point vanishes:

$$
\lim_{d \to \infty} \frac{\text{dist}_{max} - \text{dist}_{min}}{\text{dist}_{min}} \to 0
$$

In high-dimensional raw feature space, essentially every point looks roughly equidistant from every other point. "Nearest neighbor" stops being a meaningful concept, so kNN/Mahalanobis-based outlier scores flatten out and lose discriminative power exactly where detection matters most.

* Raw feature space also carries redundant, correlated dimensions (many protocol flags co-vary) that dilute genuine anomaly signal under any raw distance metric — there's no mechanism forcing the representation to be efficient.

## 2. The Manifold Reformulation

The assumption autoencoders exploit: normal network traffic, despite being embedded in a high-dimensional feature space, actually lies on (or near) a much lower-dimensional **manifold** within that space — because the features are generated by a limited number of underlying causal factors (typical protocols, typical service usage patterns, typical session shapes).

The encoder $f_\theta: \mathbb{R}^d \to \mathbb{R}^k$ (with $k \ll d$) is forced to parameterize this manifold, and reconstruction loss becomes a direct proxy for **distance from the manifold**:

$$
\mathcal{L}(x) = \|x - g_\phi(f_\theta(x))\|_2^2
$$

Trained only on benign traffic, the manifold the network learns *is* the benign manifold. Any traffic that doesn't lie near it — regardless of whether it matches a known attack signature — produces elevated $\mathcal{L}(x)$. This is the mechanism that makes it zero-day capable: the detector never needs to have seen the attack pattern, only needs a working definition of "not attack."

## 3. Threshold Dynamics — Turning a Continuous Loss Into a Decision

Reconstruction loss is a continuous score, not a verdict. Where the cutoff $\tau$ gets placed determines the entire precision/recall tradeoff, and it's the part most naive implementations get wrong.

### Static percentile threshold (naive baseline)
Compute loss on held-out validation traffic (still benign), set $\tau$ at the 95th/99th percentile:

$$
\tau = \text{Percentile}_{95}\big(\{\mathcal{L}(x_i)\}_{i=1}^{n}\big)
$$

This assumes the loss distribution is stationary — it isn't. Diurnal traffic patterns, new legitimate services, and seasonal load shifts drift the benign loss distribution over time, causing threshold decay: either false-positive creep, or worse, the threshold quietly becoming too loose and false-negative drift setting in unnoticed.

### Extreme Value Theory (EVT) thresholding
Since detection only cares about the *tail* of the loss distribution, model the tail directly instead of the whole distribution. The Peaks-Over-Threshold (POT) method fits a Generalized Pareto Distribution (GPD) to losses exceeding some low initial cutoff $u$:

$$
P(\mathcal{L} - u > y \mid \mathcal{L} > u) \approx \left(1 + \xi \frac{y}{\sigma}\right)^{-1/\xi}
$$

$\xi$ (shape) and $\sigma$ (scale) are fit via MLE on the exceedances. This gives a statistically grounded extreme quantile without assuming the full loss distribution is Gaussian — reconstruction losses are almost always right-skewed, so this assumption matters.

```python
import numpy as np
from scipy.stats import genpareto

def evt_threshold(losses: np.ndarray, u_percentile: float = 95, q: float = 0.999):
    u = np.percentile(losses, u_percentile)
    exceedances = losses[losses > u] - u
    xi, _, sigma = genpareto.fit(exceedances, floc=0)

    n, n_u = len(losses), len(exceedances)
    # invert the GPD tail to solve for the threshold at quantile q
    tau = u + (sigma / xi) * (((n / n_u) * (1 - q)) ** (-xi) - 1)
    return tau
```

### Adaptive / rolling thresholds
For production zero-day detection, $\tau$ is typically recomputed on a rolling window (EWMA over recent loss scores) so the boundary tracks legitimate drift without requiring full retraining:

$$
\tau_t = \lambda \cdot \tau_{t-1} + (1-\lambda) \cdot \text{Percentile}_{99}\big(\mathcal{L}_{\text{window}}\big)
$$

This is the actual difference between a detector that degrades silently in production and one that doesn't. Zero-day detection isn't "train once, threshold once" — the threshold needs an ongoing maintenance strategy, because the definition of "normal" traffic is a moving target, not a fixed one.

## 4. Why This Specifically Catches Zero-Days

Nothing in this pipeline references known attack patterns anywhere. Detection capability comes entirely from characterizing benign traffic and flagging deviation from it. A zero-day exploit generating structurally novel traffic (new byte-length distributions, new timing signatures, new flag combinations) will, almost by construction, sit off the learned benign manifold — producing elevated $\mathcal{L}(x)$ even though no rule or signature was ever written for it.

The trade-off: recall on genuinely novel attacks is bought at the cost of a nonzero false-positive rate on legitimate-but-rare traffic (a new but benign service rollout, a rare-but-valid protocol usage pattern) — which is exactly why threshold dynamics matter more here than in classification-based IDS. A poorly maintained threshold turns "zero-day capable" into "constant alert fatigue," and an analyst who gets paged too often stops trusting the system.

## Comparison

| Method | Handles high-dim features | Detects zero-days | Needs labels | Threshold stability |
| :--- | :--- | :--- | :--- | :--- |
| Signature-based (Snort/Suricata) | N/A — rule match | No, reactive only | No (rule authoring) | N/A |
| Fixed z-score / per-feature stats | Poor — univariate only | Partial | No | Static, brittle |
| kNN / Mahalanobis (raw space) | Poor — curse of dimensionality | Partial | No | Degrades as $d$ grows |
| Autoencoder reconstruction loss | Strong — learns compressed manifold | Yes | No | Needs EVT or adaptive $\tau$ |

For a hybrid IDS setup, reconstruction loss works well as a first-pass unsupervised gate — anything crossing $\tau$ gets routed to a downstream classifier (e.g. Random Forest) for triage, rather than trusting the autoencoder's binary call in isolation.
